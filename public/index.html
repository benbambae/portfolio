04 Projects

Homelab · flagship

Highly available, GitOps-driven Kubernetes on Proxmox

benkube is a 9-node upstream Kubernetes cluster (kubeadm) on my own Proxmox hypervisor, with three control-plane, three worker and three infra nodes. I build it from code, from the VMs up to the running apps, and every component version is pinned.

  • Infrastructure as code. OpenTofu clones the VMs from a cloud-init template using a least-privilege Proxmox API token, and Ansible prepares the nodes and bootstraps the cluster.
  • Networking. kube-vip gives a highly available API endpoint, Cilium is the CNI, MetalLB hands out load-balancer IPs, and Traefik is the ingress. Dedicated infra nodes keep platform services away from workloads.
  • GitOps. Argo CD runs an app-of-apps layout, so a git push becomes a deployment, and drift is reverted automatically. metrics-server and local-path storage complete the platform.
  • Operations. A 15-chapter runbook covers upgrades, node rebuilds, backups and troubleshooting, and hands-on labs (PV/PVC/StorageClass, S3 access) let me rehearse failures safely.
  • Next. I am planning to deploy a web3 service on the cluster, building on my wallet and trading-bot projects on GitHub.

This website

Self-hosted behind a Cloudflare Tunnel

benbambae.com is served from a small Fedora VM on the same Proxmox host. The VM opens an outbound tunnel to Cloudflare, so no inbound ports are open on the home network and the origin IP is never exposed.

  • The VM is cloned from a cloud-init template, with a static address and key-only SSH.
  • nginx serves the static site with hardened security headers and no third-party requests.
  • GitOps-style, pull-based deploys. A systemd timer tracks this GitHub repo and releases each new commit atomically through a symlink swap, which makes rollback instant.
  • Cloudflare handles TLS and DNS. Everything starts automatically after a reboot.
